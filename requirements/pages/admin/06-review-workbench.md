## 1. 页面目的与范围

查看待审核的剧目资料、分集及修改稿，对照线上内容，预览提交内容、定位问题，承载本次提交的结论与意见记录。

已确认的只读规则指审核中的已提交内容不能被直接改写；审核意见与结论的操作权限仍由后续完整流程决定，不能据此认定所有运营均可审批。

## 2. 用户确认记录

| 编号 | 已确认选择 |
| --- | --- |
| REVIEW-Q1 | 以提交对象＋版本平铺，区分剧目资料/分集/修改稿；显示剧名/集号、提交人、时间、媒体准备和审核进度，按类型/进度/时间筛选，可看同剧关联项；不据此确定审批层级 |
| REVIEW-Q2 | 显示候选与线上差异、封面、视频、积分和试看最终效果；授权预览可完整看提交视频，不真实扣分或计业务统计；意见可定位字段、集号、视频时刻 |
| REVIEW-Q3 | 通过/未通过及意见，未通过原因必填、通过意见可选；绑定提交版本/操作人/时间并保留历史，不以旧结论批准新稿，不因记录通过自动上架；权限及完整流转仍待定 |

## 3. 审核列表与对象

| 信息 | 用途 |
| --- | --- |
| 提交对象与版本 | 明确剧目资料、具体分集、首次内容或修改稿，稳定定位本次提交 |
| 剧名、集号与关联内容 | 打开当前对象，并查看同剧相关提交，不将其合并成整剧自动通过 |
| 提交人、提交时间 | 跟踪来源；展示与时间筛选的具体格式在设计阶段落实 |
| 媒体准备 | 展示对应版本的检测、转码、封面、适用试看结果，不混用旧资源状态 |
| 审核进度和已有结论 | 按完整流程提供的真实状态展示与筛选，不在本页另发明状态转换 |

列表采用版本记录平铺。分页、默认排序和空态可沿用后台常规交互建议，不能把设计默认值视作已定义多级审批或谁可操作。

## 4. 查看、对比与预览

- 查看当前提交版本与线上生效版本的资料差异；首次发布没有线上版本时明确为新增，不显示虚构旧数据。
- 覆盖封面、视频、积分及试看继承/覆盖后的最终配置，不能只展示原始默认值。
- 获授权审核预览者可完整查看提交视频，不受普通观众积分限制；预览不真实扣分、不发观看权益、不进入业务播放/解锁/完播统计。
- 意见可以关联具体字段、集号或视频时刻，便于修改定位，不要求每条意见都必须有视频时刻。
- 媒体未就绪、预览失败或资源版本不符时说明原因并提供任务入口；不能把无法预览伪装成内容通过。
- 对比线上版本不自动扩展为无限期保存和回放所有历史媒体，资源保留仍由技术方案定义。

## 5. 结论、理由与历史

| 字段 | 规则 |
| --- | --- |
| 结论 | 通过 / 未通过，具体谁可提交及何时生效由完整审核流程决定 |
| 未通过原因 | 必填，可附字段/集号/时刻定位 |
| 通过意见 | 可选 |
| 提交对象与版本 | 必须绑定本次对象，不能泛化为以后所有修改稿均通过 |
| 操作人和时间 | 记录实际操作主体与时刻，不由任意输入冒充 |
| 历史 | 保留既有记录；不以直接覆盖旧记录的方式暗中改判 |

保存或展示通过结论不自动上架。旧版本通过不代表新稿通过；修改稿和当前线上状态分开。改判是否允许、如何新增有效记录与撤销旧效力，在完整审核流转中确定。

## 6. 与媒体及发布的交接

- B-05 提供同一候选版本的真实处理结果，本页可定位到未就绪/失败的任务。
- B-07 读取与发布目标一致且有效的通过结果；不能仅根据“该剧以前通过过”判断可发布。
- 审核中提交内容只读，修改不能经媒体替换、改价等入口绕过；如何撤回、退回和生成新提交仍待完整流程。
- 完整审核流转未定义时，不能默认缺失结果为通过，或将页面预览当作已完成审批。

## 7. 明确保留的完整流转

送审触发、审批角色及分权/多级、谁可通过/退回、撤回/重提/改判、审核前后主状态变化、结果有效期与发布权限，本轮不擅自确定。

该确认版只完成工作台的信息、查看及记录规则，尚不是完整审批流程的开发规格。

## 8. 验收方向

1. 相同剧目的不同分集/版本分别定位，类型/进度/时间筛选和同剧关联正确。
2. 首次内容和修改稿对比正确，预览对应提交资源，意见能定位问题。
3. 授权预览不扣分、发权益或污染业务统计。
4. 未通过无理由不能提交该结论，通过意见可空；实际执行仍需完整流程授权。
5. 对象、版本、操作人、时间和历史可追查，旧结论不能冒充新稿结论。
6. 记录通过不会自动上架，媒体失败和流程未定义不被误判为通过。

本地基础流程已实现并测试；查看差异、字段/时间点意见、多角色分权和完整审批链仍待后续完善。

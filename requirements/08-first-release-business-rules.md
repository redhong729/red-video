## 2. 内容与状态关系

### 2.1 三类状态分开表达

| 维度 | 状态或内容 | 说明 |
| --- | --- | --- |
| 剧目生命周期 | 草稿 / 审核中 / 已上架 / 已下架 | 已确认的列表筛选状态 |
| 分集可见性 | 上架 / 下架 | 已确认独立控制，新上传默认下架，满足校验后手动上架 |
| 处理进度 | 上传、审核、转码各自的处理中、成功或失败信息 | 不以“上传成功”替代审核通过或转码完成 |

新集手动上架与修改稿发布后替换已确认；审核主体、未通过后的归属、修改稿的具体提交/审核/发布流转仍由审核页细化。修改稿不增加新的剧目主状态，也不将仍在线的整剧误标为已下架。

### 2.2 连载与上架条件

- 已确认：总集数是剧目资料，允许只完成部分分集后上架。
- 发布校验要求对外提供观看的整剧至少有一个合格拟公开或既有公开分集，目标版本媒体就绪；无需等待尚未上传的计划集数。
- 已确认：发布前检查封面、分集、转码和积分付费配置；审核是发布流程的一部分。
- 待公开内容必须有同版本有效审核通过，审核中、处理失败或只有旧版本结果的分集不跟随整剧上架自动可播；结果产生和权限待完整流转。
- 建议：整剧已上架且分集已上架，并满足审核与媒体就绪要求，才可创建新的该集观看。
- 整剧下架优先于单集上架。单集下架不应使其他可播分集一并下架。
- 对已上架整剧，最后一个上架分集也下架时整剧自动下架；新建草稿不触发此规则。恢复需人工校验上架，不自动恢复已下架分集；手动整剧下架保留原分集标记和数量口径。

## 3. 下架与积分处理

### 3.1 已确认的体验

1. 支持手动整剧下架、手动单集下架及定时下架。定时支持整剧和单集，计划可查看/修改/取消，统一北京时间 Asia/Shanghai；执行误差和冲突后续细化。
2. 下架不主动中断已经开始的观看；重新打开已下架内容时提示“视频已下架”。
3. 因下架被拒绝的当次积分操作不扣积分，且必须向用户解释原因。

### 3.2 为页面细化准备的边界建议

- “正在观看”建议先界定为已成功开始的当前分集播放；后续加载继续服务于这次观看，不能每次加载都按新打开拒绝。
- 刷新、重新打开、切换分集或自动进入下一集，建议视作新的观看入口，重新判断内容是否可用；会话的具体界定与有效期待确认。
- 整剧下架后从首页、分类和搜索的新查询中移除；旧链接保留明确的下架提示，不混同于地址不存在。
- 单集下架后如何在详情分集表中显示，留待页面细化；用户通过旧入口打开时仍需得到下架提示。
- 新的积分解锁操作在成立前再次确认整剧、分集可用性。因下架拒绝时，最终结果应为没有该次净扣分、没有误发权益，并显示提示。
- 并发下架、积分扣除与解锁成立的先后界定，以及失败时的回滚或补偿规则，需要单独细化。不能仅在按钮点击前检查一次状态。
- 用户已确认的“当次不扣”不自动扩展为所有历史已购内容退款；历史权益和补偿规则尚未确认。

## 4. 资料与分集管理范围

### 4.1 剧目资料

| 已确认字段 | 本轮记录范围 | 留待页面细化 |
| --- | --- | --- |
| 标题、简介、封面 | 草稿至少一个语言标题；发布必备英文标题/简介与封面；封面支持上传/分集截帧 | 字数、图片规格、其他语言与保存交互 |
| 分类、标签 | 一剧一个分类、多标签 | 标签数量、停用与删除后的处理 |
| 演员 | 可选姓名列表，角色名可选，不建演员库 | 字数、重复与展示细节 |
| 总集数 | 正整数，允许连载，可增减但不低于已有最大集号 | 已上传、已上架集数与集号的精确定义 |
| 付费策略 | 默认免费或按集积分；前 N 集按集号免费；单集覆盖优先；默认试看 30 秒可覆盖/关闭，修改稿发布后生效 | 真实交易、账户、扣费与退款 |
| 排序 | 默认 0、非负整数、大值优先，编辑页修改 | 前台使用位置与同值顺序 |

### 4.2 分集与媒体处理

已确认支持批量上传、按集号排序、时长、免费/积分付费、试看、单集上下架、审核与转码状态、封面截取、失败重试。

已确认集号唯一、默认标题可自定义，上传、转码、审核分别反馈结果；时长建议从实际媒体获取。B-05 已明确当前剧映射确认、冲突处理、MP4/50个/1GB起步限制、自动处理及最高1080p单兼容版本、封面、续传与受控重试/取消；具体参数、容量及资源保留留技术方案。失败不重做成功项，已上架替换保护线上与已有观看。

试看使用正片开头 X 秒，不另上传试看视频；剧级默认 30 秒，0 关闭，单集可跟随或覆盖。对适用的付费试看必须短于完整片长，免费及有效已解锁不裁剪；结束仅提示解锁，不自动扣分。不能只靠客户端暂停而向无权益用户公开整集资源。

## 5. 分类、标签与搜索

- 已确认每剧一个分类、多标签；前端可筛选分类和标签。
- 已确认模糊搜索；首期建议先支持剧名关键词部分匹配、英文大小写不敏感。
- 上述建议不等于已确认错字纠正、拼音匹配或跨语言翻译搜索；是否搜索简介、演员、分类、标签及别名待细化。
- 前端可同时选择几个标签、多标签之间取交集还是并集、关键词与筛选如何组合，均未因后台支持多标签而自动确定。
- 搜索和筛选按当前请求语言的数据与后端约定执行；前端不自行翻译剧名后再做另一套搜索判断。

## 6. 多语言的数据边界

| 内容 | 责任 |
| --- | --- |
| 导航、按钮、状态、提示等 UI | 前端 i18n；观众端英文优先，后台中英文 |
| 剧名、简介、分类、标签等业务字段 | 前端传当前语言，后端提供对应展示数据，前端直接展示 |
| 剧名与简介语言 | 发布英文必备，其他语言由后台按需维护，缺译后端回退英文；不自动翻译 |
| 分类标签的语言维护与回退 | 对应维护页继续统一，不假设已具备全部语言数据 |
| 视频字幕和音轨 | 单独的内容能力，未因 UI 多语言而默认纳入 |

建议语言切换后重新获取受语言影响的列表、详情、筛选选项与搜索结果，并保留可继续使用的筛选上下文。多语言分类、标签应关联同一个业务对象，不能因改显示名变成另一个筛选条件。具体传参形式、回退与响应结构在后续接口设计中确定。

## 7. 数据统计

已确认包含播放量、解锁量、完播率等，建议同时支持整剧汇总与单集查看。

| 指标 | 建议方向 | 待明确口径 |
| --- | --- | --- |
| 播放量 | 统计有效播放 | 起播或观看时长门槛、重复播放、匿名用户去重 |
| 解锁量 | 统计成功取得的付费权益 | 按集/整剧、人数/次数、退款或撤销是否扣回 |
| 完播率 | 同一口径下的完成观看数 / 有效播放数 | 完播阈值、统计时间、试看、跨日播放的归属 |

后台预览、失败解锁和下架拒绝不能误计为真实付费解锁。免费播放与试看也不能直接增加付费解锁量。指标未定义或交易能力未启用时应如实呈现，不用虚构数据填充。

## 8. 分期建议

本轮已将后台积分策略、单集积分价格、试看和付费配置校验纳入内容管理规划。原先“购买积分与支付后期考虑”的方向保留。

实际扣积分解锁是否随首期启用，用户本轮未明确调整，留为范围决策；因此不再写死“全部分集永久免费”，也不默认新增首期真实收款。建议内容运营与免费观看先形成闭环，启用付费时再补齐账户归属、积分来源、扣费与权益处理。

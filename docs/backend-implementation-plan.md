# 后台与数据库实施计划

日期：2026-11-18  
状态：按用户决定先实施后台登录；本地管理员登录、剧目草稿与列表、剧集条目及批量上传与媒体处理基础已完成，其余阶段按顺序推进。待确认事项不视为已定业务规则。

## 1. 目标与工作方式

在现有 PostgreSQL、NestJS API 和 React 管理页面基础上，逐步完善短剧内容管理、媒体处理、发布和运营能力。本计划面向后台实现；上线部署和商业化能力另行规划。

每个阶段都遵循同一个顺序：

1. 明确本阶段规则与验收范围，设计所需数据及约束，编写 Prisma 迁移。
2. 实现 API 和服务端校验，验证权限、异常和数据库行为。
3. 实现对应的后台页面与中英文界面，接入真实 API。
4. 验证数据、接口和页面的完整路径，记录结果；通过后再进入下一阶段。

按功能切片逐步扩展表结构，避免一次性设计所有业务表。已实现的迁移保留历史，后续变化使用新迁移；不以重建或清空已有数据作为日常升级方式。每阶段明确空态、失败反馈和重复操作行为，对关键数据约束、业务状态与异常路径进行自动化测试。

## 2. 当前基础

- PostgreSQL 18、Prisma 7 已连接；已建立管理员、会话、剧目草稿、分类和标签等基础数据表。
- 管理端支持中英文 UI、管理员登录、服务端会话、剧目草稿及剧集条目管理；媒体上传、上架确认、上下架和首页运营已实现。
- 细分角色、账号恢复、定时下架和统计仍待完善。
- API 和管理端在本地运行；管理端开发服务器代理 `/api`。生产部署、生产级认证配置与外部服务尚未配置。

## 3. 实施阶段

### 阶段一：后台账号、会话与权限（本地基础已完成）

**目标：** 在多人操作、审核或真实运营数据进入系统前，建立后台访问边界。

- 数据库：建立后台账号、会话、角色/权限与必要的操作记录，具体结构以确认的账号管理方式和权限边界为准。
- API：登录/退出、会话过期及权限校验；采用服务端会话和 HttpOnly Cookie，配合请求来源及 CSRF 防护。不可把前端按钮隐藏当作权限控制。
- 页面：B-01 登录、退出、失效提示及权限不足反馈；保持中英文 UI。
- 验收：未登录与无权限请求不能访问受保护操作；过期、退出及权限变更符合确认规则；审核及发布操作有可追溯身份。

本地首个管理员通过初始化命令创建，会话、登录和退出已实现；账号管理、密码修改、角色划分、审核职责分离及生产级安全配置仍待后续确定。本地实现不能视为可投入真实运营。

### 阶段二：剧目草稿与列表（已完成本地基础）

本阶段的页面方向和实施细节见 [剧目草稿与列表实施计划](drama-draft-list-plan.md)。

**目标：** 能新建、编辑、保存并查询剧目草稿，形成第一条真实业务闭环。

- 数据库：设计剧目稳定身份、草稿及多语言资料、分类/标签关联、演员、计划集数、排序、默认免费/积分与试看配置等基础数据及约束；预留后续线上生效版本与修改稿的演进空间。草稿不强制填写发布必填项。
- API：实现草稿创建、详情、修改与列表查询；服务端校验至少一种语言标题、正整数/非负数及适用的配置规则。列表先支持当前阶段可用的筛选与分页；需依赖审核、分集数量、上下架等数据的字段和操作在对应阶段补齐，不能用虚构值。
- 页面：实现 B-02 列表和 B-03 草稿新建/编辑的可用部分，支持手动保存、继续编辑、空态、错误及中英文 UI；明确哪些功能尚不可用。
- 验收：建剧后刷新仍可查到；编辑和筛选结果正确；语言切换保留未保存输入；草稿只需至少一种语言标题；非法输入被后端拒绝。

分类/标签采用稳定关联。现已确认停用后保留历史关联并禁止新增关联；仅未引用条目允许删除，同类型同语言名称忽略首尾空格和英文字母大小写后去重。完整列表的四状态、统计计数和批量下架需随相应能力完成，而非在第一阶段假装已实现。

### 阶段三：分类标签与分集基础（本地基础已完成）

**目标：** 能维护可用的分类、标签和分集资料，覆盖连载与计费配置。

- 数据库：完善分类/标签多语言及生命周期规则；建立分集、分集语言资料与价格/试看覆盖数据。保证同剧集号唯一并按集号升序展示。
- API：支持分类/标签维护、分集新增与修改、排序，以及按剧级默认与单集覆盖计算配置；新集默认下架。总集数不得低于已有最大集号。
- 页面：完成 B-08/B-09 必要维护能力和 B-04 分集管理基础；列表展示已具备真实来源的数量和策略。
- 验收：连载可新增分集；列表按集号升序，前 N 集免费按集号判断；覆盖与恢复跟随正确；试看 0 表示关闭；分集状态和可播放状态不混淆。

选项缺少当前语言名称时暂不回退；正式发布对停用分类及语言完整性的要求留待发布阶段确认。真实扣积分和购买不属于本阶段。

### 阶段四：上传与媒体处理（本地基础已完成）

**目标：** 从上传到兼容媒体和封面生成形成可观察、可恢复的后台流程。

- 数据库：记录上传批次、文件与分片、媒体资源、处理任务、各阶段状态及失败信息；保护已上线版本及相关资源。
- API / 处理进程：实现集号映射确认、分片续传、上传完成后的检测和独立处理、封面候选/指定时刻截帧、受控取消及重试。起步限制为 MP4、每批 50 个、每个 1GB，均可配置；目标输出 H.264/AAC、最高 1080p、保持比例且不放大。
- 页面：完成 B-05 任务列表、批次进度、异常处理、续传、重试、取消和封面选择；B-04 提供对应入口。
- 验收：冲突不会自动覆盖；单个文件失败不阻断有效项；刷新后可按约定续传；临时错误最多额外自动重试 2 次；取消不删除已完成结果或撤销线上内容；处理成功不自动上架。

开始前补齐续传有效期、编码参数、容量、进程重启恢复和资源回收的技术规则；不承诺未实测的吞吐量。

### 阶段五：发布与上下架（本地基础已完成）

**目标：** 基于明确版本完成审核、预览、发布与上下架，保护线上版本。

- 数据库：建立剧目/分集线上生效版本、待发布稿、审核对象与结论历史、发布记录；同版本结论关联不可混淆。
- API：支持候选/线上预览与发布校验；执行发布时重新校验并以事务保证状态一致；处理整剧和单集上/下架、部分发布及最后一个上架分集下架时整剧联动。
- 页面：提供上架校验及二次确认，补齐 B-02/B-04 的状态、上下架和当前页批量操作；逐项显示成功、跳过或失败。
- 验收：必填缺失阻断，其他事项提醒；确认时复核内容与状态；修改稿保存不改写线上版本；共享阻断不能绕过；合格独立目标可明确选择部分发布；下架不主动中断已开始观看，相关播放会话能力需在观众端阶段联合验证。

2026-11-19 用户调整：取消送审和审核步骤，直接在上架时二次确认；缺失必填项阻断，其他事项提示。已有审核记录保留，待审核项取消并恢复草稿。预览不真实扣分、发权益或计业务统计；本地使用及观众端限制见 [上下架](local-publication.md)。

### 阶段六：定时下架与任务可靠性

**目标：** 让已确认的整剧/单集定时下架可管理、可追踪且安全执行。

- 数据库：保存计划、目标、执行状态、时间和操作记录，保证重复执行可控。
- API / 任务进程：支持逐条创建、查看、修改和取消；按 Asia/Shanghai 表达业务时间，执行时复核最新状态并复用手动下架规则。
- 页面：在 B-02/B-04 提供计划管理、明确时区及执行结果。
- 验收：修改/取消与手动操作冲突按确认规则处理；进程重启后不丢任务、不重复产生错误结果；末集联动规则仍成立。

实施前先确认执行误差、过期时间、重复计划、冲突及失败重试规则。

### 阶段七：统计与运营完善

**目标：** 展示有明确定义和真实来源的运营指标，并完善联调。

- 数据库：按确认口径记录播放、解锁及完播所需事件或汇总，隔离预览和失败操作。
- API：提供有时间范围、筛选和权限控制的查询；区分暂无数据、真实零值和未启用。
- 页面：完成 B-10，支持整剧/单集查看及真实状态反馈。
- 验收：指标定义、去重、时间范围和延迟符合确认口径；预览不计入真实数据；未启用的交易指标不展示虚构结果。

统计依赖观众端播放事件；实际积分解锁是否首期启用、账户归属和扣费一致性仍待单独决定。购买积分、支付和广告继续作为后续方向。

## 4. 贯穿各阶段的检查

- **数据库：** 新环境可从迁移建立结构；已有数据升级不被清空；必要的唯一性、外键和事务在数据库与服务端共同保护。
- **API：** 服务端负责数据校验、状态转换和权限；错误可区分并可恢复，不依赖前端限制。
- **后台：** UI 中英文、加载/空态/失败明确；业务内容按服务端语言规则展示，不由前端自动翻译。
- **测试：** 各阶段至少验证一条数据库→API→页面主路径，以及该阶段关键异常；对发布、权限、计价和并发等高风险规则增加自动化测试。
- **实施边界：** 本地数据和视频不提交到仓库；默认不公开本地数据库与后台。任何上线、外部存储和供应商选择另行规划。
